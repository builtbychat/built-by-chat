# Captions and transcripts

Accessibility is part of the show, not a post-production extra.

## Live

- Enable and verify the current caption path separately on every broadcast destination during the unlisted rehearsal. Platform behavior can change; do not assume one output captions the other.
- Speak every poll question, option, opening time, remaining time, result, and safety-related correction. Do not make the visual overlay the only source.
- Keep host speech clear during code/build explanations, define abbreviations, and pause after major decisions.
- Captions must not cover poll options, results, lower-thirds, or important code. Check 1920×1080 and phone-sized previews.
- A moderator reports missing or badly delayed captions. Treat prolonged loss as a production defect and use verbal summaries while recovering.

## Edited recap and clips

1. Generate a timecoded draft transcript from the final audio.
2. Human-review names, code terms, town names, vote totals, sponsor disclosures, and speaker changes against the recording and authoritative records.
3. Add meaningful non-speech cues only when they affect understanding; remove filler that obscures meaning without changing the speaker's intent.
4. Export captions in the format required by each approved platform and inspect them after upload before publication.
5. Use open captions for short clips only when they stay inside platform safe areas; retain an editable caption project.

## Transcript record

Store the reviewed transcript beside the episode publishing pack, without private chat/moderation content. Corrections get a visible note and revision date. Provide concise image descriptions for important visual town changes and link the public patch notes to the final vote result.
